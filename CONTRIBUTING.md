# Contributing to AurigaX projects

This guide applies to every repository in [aurigax-ai](https://github.com/aurigax-ai) that has no
contributing guide of its own. [Ostia](https://github.com/aurigax-ai/ostia/blob/main/CONTRIBUTING.md)
has its own, written for its maintainers and their coding agents.

## Who we are

AurigaX is a team of two that builds with coding agents. We read every issue, but we work on these
projects when we can, so we cannot promise when you will hear back.

## We take issues, not pull requests, for now

For now we only accept issues. Until we have settled how outside contributions are licensed, pull
requests are limited to collaborators, and a pull request from outside the team may be closed
without review. This guide will say so when that changes.

## Opening a good issue

- Search the [existing issues](https://github.com/aurigax-ai/ostia/issues?q=is%3Aissue) first.
- Open issues in [aurigax-ai/ostia](https://github.com/aurigax-ai/ostia/issues/new/choose), including
  ones about the Homebrew tap, the APT repository, the extension marketplace and the website. Issues
  about [ghostty-web](https://github.com/aurigax-ai/ghostty-web/issues) go in that repository.
- Use the forms: Bug report, Feature request or Question. We do not use GitHub Discussions, so
  questions are issues too.
- One problem per issue. For a bug, give the version, your operating system, how you installed, and
  the steps that make it happen.

## Using AI

You can use AI tools, but you are responsible for everything you send. Read the
[AI policy](https://github.com/aurigax-ai/.github/blob/main/AI_POLICY.md).

## Security

Do not open a public issue for a vulnerability. Follow the
[security policy](https://github.com/aurigax-ai/.github/blob/main/SECURITY.md).

## Code of conduct

Everyone who takes part follows the
[Code of Conduct](https://github.com/aurigax-ai/.github/blob/main/CODE_OF_CONDUCT.md).
